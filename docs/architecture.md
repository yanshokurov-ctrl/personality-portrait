# Архитектура модуля

> Статус: **черновик**. Будет сверен с контрактами данных, утверждёнными преподавателем.

## Компоненты и поток данных

```
 registry.get_methodologies()          список методик m01…m20 в порядке опроса
            │
            ▼
 ┌──────────────────────┐   get_questions()   ┌─────────────────────┐
 │  Движок опроса        │ ─────────────────▶ │  Методика (×20)      │
 │  engine/session.py    │                     │  methodologies/      │
 └──────────────────────┘                     └─────────────────────┘
   показ вопросов, навигация,                          ▲
   приём ответов, группировка                          │ process(answers)
            │                                          │ (через runner)
            │ grouped_answers()                        │
            ▼                                          │
 ┌──────────────────────┐ ─────────────────────────────┘
 │  Сборщик результатов  │
 │  collector/           │
 └──────────────────────┘
            │ Portrait
            ▼
 ┌──────────────────────┐
 │  Интерфейс (этап 3)   │  экран опроса, экран результатов
 └──────────────────────┘
```

Главный принцип: **движок и сборщик ничего не знают о конкретных методиках**.
Всё, что специфично для методики (вопросы, ключи, подсчёт, интерпретация),
находится внутри неё. Поэтому методики на этапе 2 подключаются без изменения ядра.

## Контракт методики

Файл: `app/methodologies/base.py`. Каждая методика реализует:

| Член | Тип | Описание |
|------|-----|----------|
| `id` | `str` | `"m01"` … `"m20"` — номер из списка методик |
| `name` | `str` | Название методики |
| `get_questions()` | `→ list[Question]` | Вопросы в порядке показа |
| `process(answers)` | `dict[str, Answer] → MethodologyResult` | Обработка ответов |

Структуры данных — в `app/contracts.py`:

| Структура | Поля |
|-----------|------|
| `Question` | `id` (`"m01.5"`), `methodology_id`, `text`, `type` (`single` / `multiple` / `scale`), `options`, `required` (по умолчанию `False`; `True` — вопрос нельзя пропустить) |
| `Option` | `value` (число для ключа), `text` (что видит пользователь) |
| `Answer` | `question_id`, `value` (`int` / `list[int]` / `None` = пропущен) |
| `MethodologyResult` | `methodology_id`, `name`, `status` (`ok` / `error` / `missing`), `scales`, `message` |
| `ScaleResult` | `scale_id`, `name`, `score`, `level` (`low` / `medium` / `high` / `None`), `interpretation` |
| `Portrait` | `created_at`, `results` (по одному на методику) |

Почему у результата **список шкал**, а не один балл: у многих методик несколько шкал
(например, COPE, стили коммуникации, черты характера). Методика с одной шкалой
просто возвращает список из одного элемента.

## Использование движка

```python
from app.engine.session import SurveySession
from app.methodologies.registry import get_methodologies

session = SurveySession(get_methodologies())
while not session.is_finished():
    question = session.current_question()   # показать question.text и question.options
    current, total = session.progress()     # индикатор «Вопрос 3 из 60»
    session.answer(4)                       # или session.skip(); ValueError — недопустимый ответ
    session.next()                          # session.back() — к предыдущему вопросу
portrait = session.finish()                 # итоговый «Портрет личности»
```

`answer()` и `skip()` не переходят к следующему вопросу — переход делает интерфейс через `next()`.
Повторный ответ на тот же вопрос перезаписывает прежний.

## Обработка ошибок

Ошибка в одной методике **не ломает весь опрос**: пользователь проходит остальные
методики и получает отчёт, где проблемная методика помечена.

| Ситуация | Где обрабатывается | Что происходит |
|----------|-------------------|----------------|
| Методика падает при выдаче вопросов | `runner.load_questions` → движок | Её вопросы не показываются, методика попадает в `session.failed`, в отчёте — `error` |
| Методика вернула вопросы с чужим `methodology_id` | `runner.load_questions` | То же, что выше |
| Методика падает в `process()` | `runner.run_methodology` | Результат `error`, текст исключения в `message` |
| Методика вернула результат не по контракту | `runner.check_result` | Результат `error`, список нарушений в `message` |
| Пользователь пропустил часть вопросов | Методика | Методика сама решает, как считать (правило — на этапе 2) |
| Пользователь пропустил все вопросы методики | `runner.run_methodology` | Результат `missing` («Нет ответов») |
| Недопустимый ответ (нет такого варианта, не тот тип) | `session.answer` | `ValueError`, интерфейс просит ответить заново |
| Пропуск обязательного вопроса | `session.skip` | `ValueError`, интерфейс просит ответить |
| Пользователь остановился на середине | `session.grouped_answers` | Непройденные вопросы считаются пропущенными |
| Методика подключена дважды | `collector.collect` | `ValueError` — ошибка конфигурации |

Что видит пользователь (этап 3): при `error` — «Результат по методике временно
недоступен», при `missing` — «Вы не ответили на вопросы этой методики».

## Формат отчёта «Портрет личности»

`Portrait.to_dict()` даёт структуру, которую можно сохранить в JSON:

```json
{
  "created_at": "2026-10-20T14:05:00",
  "results": [
    {
      "methodology_id": "m01",
      "name": "Оценка особенностей личности",
      "status": "ok",
      "scales": [
        {
          "scale_id": "total",
          "name": "Общий балл",
          "score": 12,
          "level": "medium",
          "interpretation": "Средний уровень выраженности характеристики."
        }
      ],
      "message": ""
    },
    {
      "methodology_id": "m02",
      "name": "Индекс устойчивости идентичности",
      "status": "missing",
      "scales": [],
      "message": "Нет ответов на вопросы методики"
    }
  ]
}
```

Требования: в `results` ровно 20 записей (по одной на методику), без потерь и дубликатов,
в порядке опроса.

## Порядок методик

Задаётся в `app/methodologies/registry.py`. Пока это порядок из списка в задании (m01–m20),
вопросы идут блоками по методикам. Окончательный порядок — согласовать с преподавателем.

## Заглушки

`app/methodologies/stubs.py` — `StubMethodology`: N вопросов со шкалой 1–5,
балл = сумма ответов. Нужны, чтобы делать и тестировать движок и сборщик, пока нет
настоящих методик. «Сломанные» методики для тестов ошибок — в `tests/fakes.py`.
