# Правила работы команды

## Git

- Ветка `main` — только рабочий код. Напрямую в `main` не коммитим.
- Каждая задача — отдельная ветка: `feature/<кратко>`, `fix/<кратко>`, `docs/<кратко>`.
  Пример: `feature/engine-navigation`, `fix/skipped-questions`.
- Изменения попадают в `main` только через Pull Request.
- Каждый PR проверяет основной разработчик (код) или другой участник (документация).
- В PR пишем: что сделано, номер задачи, как проверить.
- Сообщения коммитов — на русском, в повелительном наклонении:
  `Добавить переход назад между вопросами`.

## Код

- Python 3.12+, стиль PEP 8.
- Имена переменных и функций — на английском, комментарии и тексты для пользователя — на русском.
- Любая новая функция движка или методики сопровождается тестом в `tests/`.
- Перед PR запускаем `pytest` — все тесты должны проходить.
- Вопросы и ключи методик не пишем в коде — только в JSON (`app/methodologies/data/`).

## Задачи и ошибки

- Все задачи — в [tasks.md](tasks.md) (позже — в GitHub Issues/Projects).
- Ошибки тестировщики оформляют как Issue по шаблону «Баг-репорт».
- Статусы задач: `К выполнению` → `В работе` → `На проверке` → `Готово`.

## Встречи

- Короткий созвон 2 раза в неделю (15 минут): что сделал, что делаю, что мешает.
- Итоги встреч документация записывает в `docs/meetings/`.
- Если задача блокирует других — сразу пишем в общий чат, не ждём встречи.

## Общие договорённости по методикам (будут дополнены на этапе 2)

- Округление баллов: _определить_
- Обработка пропущенных вопросов: _определить_
- Уровни интерпретации: низкий / средний / высокий — пороги по ключам методики
